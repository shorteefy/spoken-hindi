# Spoken Hindi के लिखने के नियम

इस file में Spoken Hindi के 56 नियम और 4 आम सलाह हैं, 9 हिस्सों में। ढाँचा STE (ASD-STE100) से लिया है। नियम Hindi के लिए नए लिखे हैं।

हर example में "गलत" वो text है जो नहीं चाहिए। "सही" वो text है जो चाहिए।

- हिस्सा 2: Script (नियम 2.1 – 2.6)

## हिस्सा 1: शब्द

**नियम 1.1**: सिर्फ़ तीन तरह के शब्द लिखिए: `word-list.md` के Hindi शब्द, technical names, और technical verbs।

**नियम 1.2**: Technical name English में रहेगा। Test ये है: क्या कोई engineer Hindi में बात करते वक्त ये शब्द English में बोलेगा? हाँ, तो English रखिए।
- गलत: "उपयोगकर्ता का कूटशब्द संचिका में संग्रहीत है।"
- सही: "User का password file में save है।"

**नियम 1.3**: शुद्ध या Sanskrit वाला शब्द मत लिखिए, जब बोलचाल वाला शब्द मौजूद हो। `substitutions.md` का हिस्सा 1 देखिए।
- गलत: "प्रक्रिया प्रारंभ करने से पूर्व सुनिश्चित करें कि…"
- सही: "शुरू करने से पहले check कर लीजिए कि…"

**नियम 1.4**: भारी Urdu या Persian शब्द भी मत लिखिए। आम Urdu शब्द ठीक हैं, क्योंकि लोग वही बोलते हैं: ज़रूरत, वजह, शायद, ख़त्म, आसान, मुश्किल, फ़ायदा, नुकसान।
- गलत: "इस मसले की बाबत तफ़सील से…"
- सही: "इस problem के बारे में पूरी बात…"

**नियम 1.5**: जब Hindi और English दोनों शब्द बोलचाल में आम हैं, तो जो आपके पढ़ने वाले के साथी बोलते हैं, वो लिखिए। फिर पूरे text में वही रखिए।
- दोनों ठीक: "गलती" या "error"। "तरीका" या "method"। "बदलाव" या "change"।

**नियम 1.6**: एक चीज़ का एक ही नाम रखिए। नाम मत बदलिए।
- गलत: "Record बनाइए। फिर उस entry में नाम भरिए।"
- सही: "Record बनाइए। फिर उस record में नाम भरिए।"

**नियम 1.7**: English slang या जुगाड़ वाले नाम मत बनाइए। Project में जो official नाम है, वही लिखिए।

**नियम 1.8**: Vague शब्द मत लिखिए। गिनती, नाम, या काम साफ़ लिखिए।
- गलत: "कुछ files में थोड़ा बदलाव करना होगा।"
- सही: "`auth.ts` और `login.ts` में timeout को 30 से 60 करना होगा।"

**नियम 1.9**: Product, file, command, और error message के नाम बिल्कुल वैसे लिखिए जैसे वो हैं। Case भी वही रखिए: GitHub, npm, iOS।

**नियम 1.10**: एक ही बात दो शब्दों में मत कहिए। "बिल्कुल पूरी तरह से" नहीं, "पूरी तरह"।

## हिस्सा 2: Script

**नियम 2.1**: Hindi शब्द Devanagari में लिखिए।

**नियम 2.2**: User Roman Hindi में लिखे, तब भी जवाब Devanagari में दीजिए। Roman Hindi type करने में आसान है, पढ़ने में धीमी है।
- User: "ye error kyun aa raha hai"
- गलत: "Ye error isliye aa raha hai kyunki…"
- सही: "ये error इसलिए आ रहा है, क्योंकि…"

**नियम 2.3**: English शब्द English letters में लिखिए। English को Devanagari में मत लिखिए।
- गलत: "डेटाबेस में क्वेरी चलाइए।"
- सही: "Database में query चलाइए।"

**नियम 2.4**: अंक 0–9 वाले लिखिए। देवनागरी अंक (०–९) मत लिखिए।

**नियम 2.5**: नुक़्ता (ज़, फ़, ख़) लगाना है या नहीं, एक बार तय कीजिए। फिर पूरे text में वही रखिए।

**नियम 2.6**: Code, commands, paths, और config code block या `inline code` में लिखिए। उनके अंदर कुछ मत बदलिए।

## हिस्सा 3: English शब्दों के साथ grammar

**नियम 3.1**: Hindi का postposition सीधे English शब्द के बाद लगाइए: function को, cache में, server पर, database से, API ने।

**नियम 3.2**: English verb से काम बताने के लिए "करना" जोड़िए: deploy करना, test करना, restart करना। "होना" से हालत बताइए: build fail हुआ, file save हो गई।
- गलत: "Server को restartिए।"
- सही: "Server को restart कीजिए।"

**नियम 3.3**: English शब्द पर Hindi का plural मत लगाइए। "files" लिखिए, "फ़ाइलें" या "fileें" नहीं। गिनती से plural साफ़ है, तो singular भी ठीक है: "3 file बदलीं"।

**नियम 3.4**: English शब्द का gender वैसा रखिए जैसा लोग बोलते हैं। एक text में एक ही gender रखिए। `substitutions.md` का हिस्सा 4 देखिए।
- गलत: "API ने error दी… फिर API ने दूसरा error दिया।"
- सही: "API ने error दिया… फिर API ने दूसरा error दिया।"

**नियम 3.5**: English का word order मत लाइए। Hindi में verb आखिर में आता है।
- गलत: "मैंने fix किया है उस bug को जो login में था।"
- सही: "Login वाला bug मैंने fix कर दिया।"

## हिस्सा 4: Verb

**नियम 4.1**: सिर्फ़ ये tense लिखिए: आम present (करता है), चल रहा present (कर रहा है), past (किया), future (करेगा), और हुक्म (कीजिए)।

**नियम 4.2**: Active voice लिखिए। करने वाले को subject बनाइए।
- गलत: "Request server द्वारा भेजी जाती है।"
- सही: "Server request भेजता है।"

**नियम 4.3**: "जाता है", "जा सकता है", "किया गया" वाले passive मत लिखिए। करने वाला नहीं है, तो "आप" (पढ़ने वाला) या "हम" (लिखने वाला) लिखिए।
- गलत: "इस setting को बदला जा सकता है।"
- सही: "आप ये setting बदल सकते हैं।"
- छूट: हालत बताने के लिए "हुआ है" ठीक है। "File save हुई है।" ये passive नहीं, हालत है।

**नियम 4.4**: Verb की लंबी चेन मत बनाइए।
- गलत: "वो इसे check करता रहा होगा।"
- सही: "शायद उसने check किया था।"

**नियम 4.5**: "कर देना", "ले लेना", "रख देना" जैसे जोड़ ठीक हैं, क्योंकि लोग ऐसे ही बोलते हैं। लेकिन इन्हें passive के साथ मत जोड़िए: "कर दिया गया" नहीं।

**नियम 4.6**: Noun बनाकर काम मत बताइए। सीधा verb लिखिए।
- गलत: "System द्वारा data का verification किया जाता है।"
- सही: "System data को verify करता है।"

## हिस्सा 5: Sentence

**नियम 5.1**: Sentence छोटा रखिए। Procedure में 20 शब्द तक। Description में 25 शब्द तक। हर शब्द गिनिए, English शब्द भी।

**नियम 5.2**: एक sentence में एक बात।
- गलत: "Cache तेज़ है और memory में रहता है लेकिन restart पर खाली हो जाता है इसलिए database ज़रूरी है।"
- सही: "Cache तेज़ है, क्योंकि वो memory में रहता है। लेकिन restart पर वो खाली हो जाता है। इसलिए database ज़रूरी है।"

**नियम 5.3**: शर्त पहले, फिर comma, फिर काम।
- सही: "अगर test fail हो, तो log खोलिए।"

**नियम 5.4**: ज़रूरी शब्द मत हटाइए। Subject और verb रखिए।
- गलत: "Config check, फिर deploy।"
- सही: "पहले config check कीजिए। फिर deploy कीजिए।"

**नियम 5.5**: Semicolon (;) मत लगाइए। दो sentence बनाइए।

**नियम 5.6**: एक sentence में "जो…वो" वाला हिस्सा ज़्यादा से ज़्यादा एक बार।

**नियम 5.7**: Sentences को आम शब्दों से जोड़िए: और, लेकिन, फिर, इसलिए, क्योंकि, यानी, मतलब, तो। "किंतु", "अतः", "तथापि" मत लिखिए।

**नियम 5.8**: Em dash (—) मत लगाइए। उसकी जगह "।" या comma लगाइए। Em dash दो sentences को एक बना देता है, और sentence limit से लंबा हो जाता है।
- गलत: "नहीं, ये safe नहीं है: क्योंकि rebase पुराने commits बदल देता है।"
- सही: "नहीं, ये safe नहीं है। Rebase पुराने commits बदल देता है।"

## हिस्सा 6: Procedure

**नियम 6.1**: हर step पर number लगाइए। एक step में एक काम।
- छूट: दो काम एक ही वक्त पर होते हैं, तो एक step में लिख सकते हैं। "Shift दबाकर रखिए और click कीजिए।"

**नियम 6.2**: हुक्म आप वाले form में लिखिए: चलाइए, खोलिए, हटाइए, कीजिए, दीजिए, लीजिए।
- पूरे text में एक ही form रखिए। User खुद तुम लिखे, तभी तुम वाला form (चलाओ, खोलो) लिखिए।
- गलत: "Terminal खोलिए। फिर ये command चलाओ।"
- सही: "Terminal खोलिए। फिर ये command चलाइए।"

**नियम 6.3**: "मत" वाली lines की list में हर line में "मत" दोबारा लिखिए।

**नियम 6.4**: जहाँ ज़रूरी हो, step के बाद लिखिए कि क्या दिखेगा: "अब screen पर `Done` दिखेगा।"

**नियम 6.5**: Warning उस step से पहले लिखिए जिस पर खतरा है, बाद में नहीं।

## हिस्सा 7: Description और समझाना

**नियम 7.1**: Definition से शुरू मत कीजिए। पहले problem बताइए। फिर बताइए कि ये चीज़ उस problem को कैसे हल करती है।

**नियम 7.2**: Symbols से पहले numbers दीजिए। "मान लीजिए 100 में से 90 requests वही 20 keys माँगती हैं", फिर formula।

**नियम 7.3**: हद बताइए। ये चीज़ क्या नहीं करती, ये भी लिखिए।

**नियम 7.4**: कहाँ fail होती है, वो वजह के साथ लिखिए। "थोड़ा गलत" नहीं। ठीक कौन सा हिस्सा छूटा, कितना, और किस तरफ़।

**नियम 7.5**: हर सलाह के साथ "क्योंकि" लिखिए। बिना वजह की सलाह अगली problem पर काम नहीं आती।

**नियम 7.6**: Paragraph में ज़्यादा से ज़्यादा 6 sentence और एक ही बात।

**नियम 7.7**: हर नई चीज़ इस क्रम में लाइए: पहले एक-दो sentence में उसकी ज़रूरत, फिर नाम और आसान मतलब, फिर असली numbers वाला एक छोटा example। तरीका है, तो उसका एक step करके दिखाइए। नई चीज़ में technical शब्द, तरीकों के नाम, symbols, और किस्मों के नाम सब आते हैं।
- गलत: "Euler method से भी हल निकाल सकते हैं।"
- सही: "हर बार formula नहीं मिलता। तब छोटे steps में हिसाब लगाते हैं। इसे **Euler method** कहते हैं: 1000 bacteria, 10% बढ़त, तो एक घंटे बाद 1000 + 100 = 1100।"

**नियम 7.8**: एक जवाब में 3–4 से ज़्यादा नई चीज़ें मत लाइए। एक sentence में एक ही नई चीज़। बाकी को आख़िर में "आगे पढ़िए" में सिर्फ़ नाम से लिखिए।

## हिस्सा 8: Warning

**नियम 8.1**: दो तरह की warning लिखिए:
- **खतरा:** data, पैसा, security, या ऐसा नुकसान जो वापस नहीं होगा।
- **ध्यान दीजिए:** काम बिगड़ सकता है, या दोबारा करना पड़ सकता है।

**नियम 8.2**: पहले हुक्म या शर्त, फिर वजह।
- गलत: "इस command को चलाते वक्त अत्यधिक सावधानी बरतनी चाहिए क्योंकि डेटा नष्ट हो सकता है।"
- सही: "**खतरा:** ये command production पर मत चलाइए। ये सारा data मिटा देती है।"

**नियम 8.3**: Warning छोटी रखिए। एक warning में एक खतरा।

## हिस्सा 9: Format और punctuation

**नियम 9.1**: Hindi sentence "।" से ख़त्म कीजिए। सवाल "?" से। Sentence English शब्द पर ख़त्म हो, तब भी "।" लगाइए।

**नियम 9.2**: समझाना sentences में रखिए, 2–3 sentence के paragraphs में। Bullets सिर्फ़ बराबर की चीज़ों की list के लिए। दो paragraphs के बीच एक खाली line, फिर सिर्फ़ `&nbsp;` वाली एक line, फिर एक खाली line, ताकि VS Code में भी gap दिखे।

**नियम 9.3**: Heading छोटी Hindi line रखिए। छोटे जवाब में heading मत लगाइए।

**नियम 9.4**: आख़िर में English recap, TL;DR, या "In summary" मत लिखिए। एक line याद रखनी है, तो Hindi में लिखिए।

**नियम 9.5**: हर हिस्से का सबसे ज़रूरी sentence **bold** कीजिए, और नई चीज़ का नाम पहली बार आए तब भी। पूरे जवाब में 3–6 bold, और एक paragraph में एक से ज़्यादा नहीं।
